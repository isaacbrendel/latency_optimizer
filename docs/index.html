A Comparative Evaluation of High-Throughput Producer-Consumer Architectures in the Go Runtime: Channels vs. Lock-Free Disruptor Ring Buffer

July 18, 2026

Abstract

This paper evaluates the performance characteristics of four producer-consumer fan-out architectures implemented in Go: Simple Fan V1 (struct copying), Simple Fan V2 (pointer passing), Simple Fan V3 (batched pointer passing), and RingBuffer V6 (a Disruptor-inspired circular queue with sync.Cond signaling, individual reader sequence tracking, pointer recycling via sync.Pool, and lock-free read paths). Utilizing varying trade volumes (10,000 to 1,000,000) and subscriber counts (10 to 2,000) under real-time market data feed simulation, we demonstrate that Go channels suffer from linear latency scaling and massive allocation churn. Specifically, at 2,000 subscribers and 50,000 trades, Simple Fan V1 allocates 328.8 MB of heap memory, while RingBuffer V6 allocates only 538 KB—representing a 611x decrease in total memory allocation and a 36x reduction in latency.

1. Tested System Architectures

To replicate Coinbase's optimization journey, we evaluate four sequential architectures in this experiment:

  • Simple Fan V1 (Struct Value Copy): The standard Go implementation. The producer publishes an 80-byte Trade struct to an input channel. A broker loop reads this and copies the struct to each subscriber's channel, incurring significant data copying.
  • Simple Fan V2 (Pointer Copy): Instead of copying the 80-byte struct, we pass an 8-byte pointer *Trade. This reduces copying overhead but introduces heap allocations for the published structs.
  • Simple Fan V3 (Batched Pointers): Rather than passing trades individually, we pack them into slices (default batch size of 128) and push these slices to the subscriber channels, mitigating channel lock contention.
  • RingBuffer V6 (Disruptor Lock-Free): A circular pre-allocated array of size 2,048. We track each consumer's position independently using atomic sequence counters. The read path is completely lock-free; readers only block on a sync.Cond when the queue is empty. Substituted objects are recycled via sync.Pool to eliminate GC churn.

The producer polls the live Coinbase API for the BTC-USD order book every 1.5 seconds. Incoming trades are pushed into the Ring Buffer using batch writes. Three concurrent consumer goroutines read the trades in real-time.
