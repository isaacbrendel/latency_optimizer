1. Architectural Trajectory & Milestones

Phase 1: Naïve Channel Fan-Out Architecture (Baseline V1) 164.20 ms / op

Design: Producer broadcast incoming L2 trade objects to 500+ subscriber goroutines using unbuffered Go channels (chan *Trade) guarded by a global sync.RWMutex lock.

  • Bottlenecks: Heavy OS thread context switching during market volatility spikes; severe lock contention on read paths.
  • Memory Overhead: Heap allocation of heap trade pointers resulted in 35.2 MB / op and 488 allocs / op, causing frequent Stop-The-World (STW) garbage collection pauses.
Phase 2: Buffered Worker Pools & Batched Mutex Acquisition (V2 & V3) 25.00 ms / op

Design: Replaced unbuffered channel broadcasts with dedicated ring buffers per subscriber and implemented batched mutex acquisition.

  • Improvements: Reduced memory allocations from 35.2 MB down to 1.2 MB (29x reduction).
  • Remaining Issues: Slow subscribers could still stall the producer when individual subscriber buffers reached capacity.
Phase 3: Lock-Free Circular Ring Buffer (Disruptor V6 Architecture) 626 µs / op (350x Speedup)

Design: Constructed a single pre-allocated circular ring buffer array (2048 slots) storing pointerless value structs, using atomic sequence numbers (atomic.Int64) and 64-byte L1 cache-line isolation.

  • Cache Line Padding: Added [59]byte padding around atomic sequence fields to isolate CPU L1 cache lines and eliminate false sharing across core threads.
  • Zero Mutex Read Path: Readers access memory concurrently via lock-free atomic CAS and sequence comparison.
Phase 4: Struct Layout & Compiler Padding Bit-Packing Exact 40-Byte Struct Footprint

Design: Reordered fields inside CompactTrade strictly by alignment size (int64 → uint16 → uint8), packing metadata (Sequence uint16, Flags uint8, VenueID uint8) directly into implicit compiler alignment gaps.

  • Result: Zero trailing padding bytes. Exactly 40 Bytes per struct, fitting 1.6 trade records per 64-byte L1 cache line.
Phase 5: FlatBuffers Zero-Copy Binary Wire Format 1.03 ns / op • 0 B/op • 0 Allocs

Design: Defined a binary FlatBuffers schema (trade.fbs) and implemented zero-allocation accessor methods in flatbuffers_trade.go.

  • Speedup: Bypasses JSON unmarshaling and reflection, decoding binary fields in 1.03 nanoseconds with zero heap allocations.
Phase 6: Non-Blocking Slow-Reader Eviction Engine Zero Producer Write Stalls

Design: Implemented PublishBatchEvicting(). If a non-blocking market data subscriber lags behind by more than buffer capacity (2048 slots), the producer fast-forwards the reader sequence pointer to the current buffer head and increments evictedCount without blocking write execution.

Phase 7: Multi-Venue Ingress & 4-Consumer Telemetry Workstation 4 Concurrent Consumers • In-place DOM Updates

Design: Integrated multi-venue data streams from Coinbase (`CB`), Robinhood (`RH`), and Binance (`BN`) into 4 concurrent non-blocking readers (W, BOT, IND, AUDIT). Upgraded Section 3.1 with an atomic pointer telemetry table, locked container bounds, and in-place DOM node updates to eliminate layout quivering.
